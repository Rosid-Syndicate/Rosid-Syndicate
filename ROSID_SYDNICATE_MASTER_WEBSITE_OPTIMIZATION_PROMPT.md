- create credential theft tooling
- create persistence mechanisms
- create destructive exploits
- attack unrelated systems
- intentionally damage data
- delete production data
- expose secrets
- print secrets into logs
- commit `.env` files
- weaken authentication
- weaken authorization
- bypass legitimate access controls
- intentionally lock out legitimate users

Security work must preserve existing legitimate functionality.

## 1.2 Production safety

Before major changes:

1. inspect the current architecture
2. identify the exact files involved
3. explain the change intent
4. prefer small reversible changes
5. preserve APIs and data contracts unless a change is genuinely necessary
6. use focused commits
7. create a checkpoint/branch before broad refactors when tooling allows
8. re-run validation after each substantial change

Never use “rewrite the whole app” as the default strategy.

## 1.3 Evidence first

Never state:

- “this is broken”
- “SEO is bad”
- “security is weak”
- “performance is slow”
- “the UI is inconsistent”

without evidence from one or more of:

- source code
- rendered DOM
- browser behavior
- request/response headers
- measured performance
- screenshots
- test output
- build output
- console output
- dependency audit
- database policy/configuration
- deployment configuration

When a fact cannot be verified, label it:

- **Verified**
- **Likely**
- **Needs manual verification**

# 16. CRITICAL INDEXABILITY DIRECTIVE

The goal for public pages is **discoverable and indexable unless there is a legitimate reason not to index them**.

Search the entire codebase for:

- `noindex`
- `nofollow`
- `googlebot`
- `robots`
- `index: false`
- `follow: false`
- `X-Robots-Tag`
- `Disallow`

Remove unnecessary public-page indexing restrictions.

Specifically audit:

- `layout.tsx`
- `page.tsx`
- route metadata
- metadata utilities
- route handlers
- middleware
- reusable components
- SEO utilities
- generated metadata
- dynamic pages
- programmatic pages
- `robots.txt`
- response headers
- deployment configuration

Check for:

```html
<meta name="robots" content="noindex">
<meta name="googlebot" content="noindex">
```

Check for Next.js metadata such as:

```ts
robots: {
  index: false
}
```

Check for HTTP headers such as:

```http
X-Robots-Tag: noindex
```

Remove indexing restrictions from legitimate public pages.

- request frequency limits
- abuse scoring
- suspicious request signals
- progressive challenges
- temporary blocks
- account throttling
- honeypots
- duplicate detection
- idempotency
- request cost controls

Do NOT rely only on User-Agent.

Classify traffic conceptually as:

### NORMAL HUMAN
Normal access.

### LEGITIMATE SEARCH CRAWLER
Allow public SEO content.

### AUTHENTICATED USER
Apply account and endpoint limits.

### VENDOR
Apply vendor-specific quotas and permissions.

### ADMIN
Apply stronger authentication and logging.

### UNKNOWN AUTOMATION
Observe and rate-limit intelligently.

### SUSPICIOUS AUTOMATION
Challenge or throttle.

### ABUSIVE TRAFFIC
Temporary or longer block according to risk.

Do not:

- CAPTCHA every page
- block every bot
- block entire countries without a business reason
- use extremely low global limits
- destroy SEO
- lock out real customers

- login
- signup

- OTP
- email verification
- contact

- search
- listings
- vehicle listing queries
- API endpoints
- uploads

- AI/API proxy endpoints if any

Rate-limit by combinations of:

- account
- endpoint
- method
- request cost
